This section defines the relation checks that constitute the proof system.
All arithmetic is over the fixed-point integer encoding ($\fpscale = 1000$)
implemented by the Python relation layer and Rust/SP1 backend. Statements are
about integer-arithmetic equivalence, not about exact real-valued PyTorch
execution.

\subsection{Replay Membership}

The membership relation (\Cref{fig:merkle-tree}) takes a transition $\tau_i$
and proves it belongs to the committed dataset:
\begin{equation}\label{eq:membership}
  R_{\mathrm{mem}}(\mroot;\tau_i,\mathit{idx}_i,\pi_i)=1
  \iff V_i=1,
\end{equation}
Here, $V_i$ denotes the predicate that hashes $\tau_i$, follows the sibling
path $\pi_i$ at index $\mathit{idx}_i$, and compares the result with $\mroot$.
The path $\pi_i = (h_1, \ldots, h_d, b_1, \ldots, b_d)$ contains sibling hashes
and direction bits.
Dataset-size scaling cases for $N \in \{1\text{k}, 10\text{k}, 100\text{k}\}$
leaves are SP1 proof-verified.

\subsection{Bellman Target and TD Arithmetic}

The TD relation verifies the fixed-point Bellman target computation for a
single transition $(s, a, r, s', d)$:
\begin{align}
  y &= r_{\mathrm{fp}} + \gamma_{\mathrm{fp}} \cdot (1 - d) \cdot
       Q_{\bar\theta,\mathrm{fp}}(s', a^*) / \fpscale, \label{eq:td-target}\\
  \delta &= Q_{\theta,\mathrm{fp}}(s, a) - y, \label{eq:td-error}\\
  \ell &= L_{\mathrm{SmoothL1,fp}}(\delta), \label{eq:td-loss}
\end{align}
where subscript ``fp'' denotes fixed-point representation. In the TD~MVP
relation, Q~values are free witnesses and $a^*$ is the claimed target action.
In model-grounded relations (Forward-TD~MLP, training update, training
fragment), Q~values and the Double-DQN selected action are derived from
committed MLP weights.

\subsection{Forward-TD MLP}

The Forward-TD~MLP relation binds quantized online and target model weights,
executes a Linear--ReLU--Linear forward pass in fixed point, checks
$\arg\max$ action selection for the online network, derives the selected
target value from the target network, and recomputes the SmoothL1 loss:
\begin{equation}\label{eq:forward-td}
  Q_\theta(s) = W_2 \cdot \max(W_1 \cdot s + b_1, 0) + b_2,
\end{equation}
where all multiplications include fixed-point rescaling by $\fpscale$.
The relation additionally checks that the public model commitment matches
$\mhash(W_1 \| b_1 \| W_2 \| b_2)$.

\subsection{Backpropagation and One-Step SGD}

The one-step training-update and one-step SGD tiny relations extend the
forward pass with gradient computation. Given SmoothL1 derivative
\begin{equation}\label{eq:smoothl1-grad}
  \frac{\partial L}{\partial \delta} =
  \begin{cases}
    \delta & \text{if } |\delta| < \fpscale, \\
    \mathrm{sign}(\delta) \cdot \fpscale & \text{otherwise,}
  \end{cases}
\end{equation}
the relation recomputes the fixed-point backpropagation path through the
Linear--ReLU--Linear network, computes SGD deltas
$\Delta W = -\eta \cdot \nabla_W L / \fpscale$, applies the weight update
$W' = W + \Delta W$, and verifies that the post-update checkpoint hash matches
$\mhash(W')$. The supported update is simple SGD for canonical tiny vectors;
Adam and batch sizes $>1$ are not currently proved.

\subsection{Checkpoint and Target-Network Relations}

Checkpoint hashes bind model states across updates. For a sequence of $k$
update steps, the chain requires:
\begin{equation}\label{eq:checkpoint-chain}
  \mhash(W_{t+1}) = \mhash\bigl(\mathsf{SGDUpdate}(W_t, \nabla_t)\bigr)
  \quad \forall\, t \in \{0, \ldots, k{-}1\}.
\end{equation}
Training fragments additionally check target-network synchronization: at
configured intervals, the relation verifies that the target checkpoint hash
equals the online checkpoint hash.

\subsection{Proof-Manifest Chunk Chains}

The aggregation relation operates over an ordered sequence of child proof
manifests $\{M_1, \ldots, M_c\}$ where each $M_j$ represents an externally
verified $k=8$ training fragment. The relation checks:
\begin{itemize}[leftmargin=1.5em]
  \item Child manifest hashes and public-input hashes match the aggregate
  input.
  \item All children share the same dataset root and config hash.
  \item The output checkpoint of $M_j$ equals the input checkpoint of
  $M_{j+1}$.
  \item Target checkpoint links are consistent across chunk boundaries.
  \item Aggregate roots cover the declared step ranges.
\end{itemize}
This is not true recursive aggregation: the aggregate SP1 guest does
not execute a verifier for child proof bytes.

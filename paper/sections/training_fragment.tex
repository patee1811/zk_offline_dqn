This section describes how individual relation proofs are composed into
multi-step training fragment proofs and further aggregated via proof-manifest
chunk chains.

\subsection{Training Fragment Proof}

The training fragment proof composes the one-step update relation over a short
deterministic trace of $k$ steps. For each step $t \in \{0, \ldots, k{-}1\}$,
the fragment relation verifies the complete sequence shown in
\Cref{fig:training-fragment}.

\Cref{alg:training-fragment} formalizes the per-step verification within a
$k$-step fragment.

\begin{algorithm}[!t]
\caption{$k$-Step Training Fragment Verification}
\label{alg:training-fragment}
\begin{algorithmic}[1]
\Require Initial checkpoint $W_0$, target checkpoint $\bar{W}_0$,
  seed $\sigma$, Merkle commitment $\mroot$, steps $k$
\Ensure Final checkpoint $W_k$ is correct
\For{$t = 0$ to $k - 1$}
  \State $i_t \gets \mathsf{DeterministicSample}(\sigma, t)$
  \Comment{Minibatch index}
  \State \textbf{assert} $R_{\mathrm{mem}}(\mroot;\, \tau_{i_t},
    i_t, \pi_{i_t})$
  \Comment{Replay membership}
  \State $Q_s \gets \mathsf{ForwardMLP}(W_t, s_{i_t})$
  \Comment{Online Q at current state}
  \State $Q_{s'} \gets \mathsf{ForwardMLP}(W_t, s'_{i_t})$
  \Comment{Online next-state Q}
  \State $\bar{Q}_{s'} \gets \mathsf{ForwardMLP}(\bar{W}_t, s'_{i_t})$
  \Comment{Target next-state Q}
  \State $a^* \gets \arg\max_{a'} Q_{s'}[a']$
  \State $y \gets r_{i_t} + \gamma(1 - d_{i_t}) \bar{Q}_{s'}[a^*]
    / \fpscale$
  \State $\ell \gets L_{\mathrm{SmoothL1}}(Q_s[a_{i_t}] - y)$
  \State $\nabla \gets \mathsf{Backprop}(W_t, \ell)$
  \State $W_{t+1} \gets W_t - \eta \cdot \nabla / \fpscale$
  \Comment{SGD update}
  \State \textbf{assert} $\mhash(W_{t+1}) = \mathsf{claimed\_ckpt}_{t+1}$
  \If{$(t + 1) \bmod T_{\mathrm{sync}} = 0$}
    \State $\bar{W}_{t+1} \gets W_{t+1}$
    \Comment{Hard target sync}
  \EndIf
\EndFor
\State \Return $W_k$
\end{algorithmic}
\end{algorithm}

The one-step training update ($k=1$) is the base case: it proves a single
canonical batch-size-1 update and binds the pre-update checkpoint to the
post-update checkpoint. The multi-step fragment repeats this relation and
requires each output checkpoint to match the next input checkpoint. Target
network state is linked separately so that tampering with sync events is
detected. SP1 proof provenance covers $k \in \{1, 4, 8\}$. Longer fragments
$k \in \{16, 32, 128\}$ have execute/reference validation only and are not
treated as proof-backed claims.

\subsection{Proof-Manifest Chunk-Chain Aggregation}

For training traces longer than $k=8$ steps, the system uses proof-manifest
chunk-chain aggregation (\Cref{fig:chunk-chain}). The aggregate proof binds
$c = T / k$ externally verified child proof manifests, where each manifest
represents a $k=8$ training fragment.

The aggregation relation checks the following for $T \in \{32, 64, 128\}$:

\begin{enumerate}[leftmargin=1.8em]
  \item Each child manifest hash $\mhash(M_j)$ matches the aggregate input.
  \item Each child public-input hash matches the expected value.
  \item All children share the same dataset root and config hash.
  \item The output checkpoint of $M_j$ equals the input checkpoint of
  $M_{j+1}$ (online and target checkpoints).
  \item Aggregate roots cover the declared step ranges without gaps.
\end{enumerate}

\noindent\textbf{Important limitation.} This is proof-manifest-chain
aggregation, not true recursive aggregation. The aggregate SP1 guest does not
run a verifier for child proof bytes. Child proofs are externally verified and
then represented by their manifest hashes inside the aggregate relation. True
recursive child-proof verification remains future work.
